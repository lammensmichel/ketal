# Work Item: Room connectée persistante & visible dans /rooms

## Description

Corriger le bug : une room créée par un utilisateur **connecté** n'apparaît pas dans
`/rooms` car aucun `game_members` hôte n'est créé. Créer ce member de façon idempotente
et réutiliser une room `idle` existante plutôt que d'en créer une nouvelle à chaque clic
(une room = conteneur persistant de participants pour rejouer des parties).

## Acceptance Criteria

- [ ] À la création d'une room par un utilisateur connecté (non anonyme), un
      `game_members` de rôle `host` (`userId` = utilisateur courant) est créé et
      `room.hostMemberId` est mis à jour (pattern `enterRoom()`).
- [ ] La room apparaît dans `/rooms` et dans le carrousel « parties récentes » de l'accueil.
- [ ] Idempotence : pas de doublon de member hôte ni de room si elle existe déjà.
- [ ] Réutilisation : si l'utilisateur a déjà une room `idle` non terminée, la reprendre
      au lieu d'en créer une nouvelle (pas de prolifération de `Solo-{timestamp}`).
- [ ] Utilisateur **anonyme** : comportement solo inchangé (room non listée dans `/rooms`).
- [ ] Aucune régression sur `create-room` / `join-room` ni sur les specs existantes.

## Technical Notes

- Cause racine : `RoomService.getMyRooms()` (room.service.ts:286) liste via
  `MemberService.getMembersByUserId` ; `createRoom()` met `hostMemberId:''` sans member.
- Centraliser dans `RoomService` (injecte déjà `memberService` + `authService`).
- Attention : `createSoloRoom()` est appelé en arrière-plan (`solo-room.service.ts:51`)
  et dans `players-list.toggleInvite()` → idempotence obligatoire.
- Réutiliser `CreateMemberData` (member.service.ts) ; rôle `host`, `userId` non nul.
