# Work Item: Migration backend — nickname utilisateur + collection friendships

## Description

Préparer le backend partagé **fug-backend** (Appwrite/MariaDB) : ajouter un champ
`nickname` aux utilisateurs (pour la recherche d'amis par pseudo) et créer la collection
`friendships` modélisant des favoris **unilatéraux**.

## Acceptance Criteria

- [ ] Champ `nickname` ajouté aux utilisateurs (unique, indexé pour la recherche),
      avec migration appliquée et rétrocompatible (valeur par défaut / nullable géré).
- [ ] Collection Appwrite `friendships` créée : `ownerUserId`, `friendUserId`,
      `createdAt` (favoris unilatéraux, pas de status d'acceptation).
- [ ] Permissions : chaque utilisateur lit/écrit uniquement ses propres `friendships`.
- [ ] Index/contrainte évitant les doublons (`ownerUserId` + `friendUserId`).
- [ ] Documentation de la migration + version minimale de fug-backend notée.

## Technical Notes

- Cross-repo : modifications dans `fug-backend` (voir CLAUDE.md « Backend Dependency »).
- Décision PO : amitié = favoris unilatéraux (pas de flux pending/accepted).
- Recherche par pseudo nécessite l'unicité + un index sur `nickname`.
- Prévoir l'attribution d'un `nickname` par défaut aux comptes existants (ex. dérivé du
  nom/email) pour ne pas casser la recherche.
